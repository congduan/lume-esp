311:returns `{status, body, contentLength, truncated}` or a negative error code. `body` is a string or ArrayBuffer (at most 16 KiB); response text is capped at 32 KiB and backed by PSRAM while in C. Headers are string values, at most 12 entries. Set `Content-Type` to `application/json` or `application/x-www-form-urlencoded` as appropriate. GET remains available through `httpGet`. Request timeout defaults to 30 seconds and is capped at 120 seconds. HTTPS verifies with IDF's enabled certificate bundle by default; `caPem` supplies a custom CA. Only an explicit `httpsInsecure: true` disables certificate verification for that request, and should be used only for a controlled test endpoint. `httpsInsecure` and `caPem` are mutually exclusive: passing both returns `-1` (invalid input) before any HTTP client is created. `httpGet` shares the same native request helper, so the same `-1` applies there; supply neither (certificate bundle) or exactly one. TLS needs a valid system clock for certificate date validation; the app or board should synchronize time with SNTP before a verified HTTPS request. HTTP status codes are returned in the response; `-1` means invalid input, `-2` transport failure, `-3` WiFi unavailable, and `-5` detected timeout.
